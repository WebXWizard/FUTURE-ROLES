# Exploratory Testing

Exploratory testing means learning, designing, and executing tests at the same time.

Use it when:

- Requirements are unclear.
- New feature behavior needs discovery.
- Time is limited.
- Complex workflows may hide unexpected defects.

Good exploratory testing is not random.

Use charters:

```txt
Explore checkout payment failure paths for data loss, error messages, and retry behavior.
```

Record:

- Area tested
- Data used
- Observations
- Defects found
- Risks remaining
