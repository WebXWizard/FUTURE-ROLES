# Requirement Analysis

Requirement analysis is where QA finds missing, unclear, or risky details before testing starts.

Check for:

- Clear business goal
- User role
- Preconditions
- Input rules
- Expected output
- Error handling
- Boundary values
- Security expectations
- Performance expectations
- Acceptance criteria

Questions QA should ask:

- What should happen when data is invalid?
- What roles can access this feature?
- What are the mandatory and optional fields?
- Are there limits for length, amount, date, or quantity?
- What is the expected behavior on network failure?
- What is the expected behavior on duplicate data?
